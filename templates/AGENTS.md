# 專案開發指示

## 共用 coding rules

- 修改程式前，讀取根目錄的 `.coding-rules/rules/core.md`。
- 修改 Python 時，另讀 `.coding-rules/stacks/python.md`。安裝時僅在已複製 Python 規則的專案保留本條；其他語言只加入已實際安裝的規則入口。
- 根目錄 `coding-rules.md` 中明訂的約定優先於 `.coding-rules/` 內的共用與語言規則。衝突時依專案約定執行，指出採用條文與差異；未另訂的部分仍遵循共用與語言規則。例如：專案明訂僅使用全域 debug 開關時，依此執行，不強制增加模組開關。
- 根目錄已有 `coding-rules.md` 時，修改前一併閱讀。它保存專案的具體設計與例子；安裝通用規則時不建立此檔。若已有其他專案規範文件，沿用該文件並填入實際路徑。
- 開發中需要新增或修改規則時，主動提出原因、適用情境與附例子的草案，取得使用者同意後再更新。例如：多個模組各自增加 debug 開關時，提出共用日誌與除錯控制的方案。

## 專案約定

填入架構文件、重要模組邊界與專案例外。專案的具體例子可使用實際名稱與路徑；區分現行做法與待採用提案。例如：現行只有全域 debug 控制時，將模組獨立控制列為提案。

## 驗證指令

填入此專案可執行的 formatter、lint、型別檢查與測試指令。
