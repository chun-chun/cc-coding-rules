# CC Coding Rules

供大型專案選用的開發規則。各專案透過根目錄的 `AGENTS.md` 指定要讀的規則，並使用自己的 lint、型別檢查與測試指令驗證變更。

每條規則附上例子。通用規則用語言中立的情境說明設計原則，不使用來源專案名稱或專屬介面；語言規則提供各語言的實作範例。專案版 `coding-rules.md` 可補充實際設定、日誌與功能分類的用法。安裝時會說明這份文件的用途，但不建立它。開發中需要增修規則時，agent 應主動提出原因與草案，取得同意後更新。

對目標專案的 agent 說：「讀取 `./cc-coding-rules/INSTALL.md`，把這套規則安裝到目前專案。」如果下載在其他位置，提供實際路徑。

- [安裝與更新](INSTALL.md)
- [共用規則](rules/core.md)
- [Python 規則](stacks/python.md)
- [專案入口範本](templates/AGENTS.md)

要繼續整理規則時，在 Codex 開啟本 repo 並建立新 session。先讀本 repo 的 [維護指示](AGENTS.md)。

## 語言與專案分工

目前提供 Python 規則，未來預計加入 C 規則；C 規則尚未提供，不能視為已安裝或引用。混合語言專案可同時採用已提供的相關規則，修改哪種語言就讀取對應規則。

例如：共用規則要求集中設定，Python 可沿用既有字典或 dataclass，C 可用設定結構體；具體選擇依專案既有設計。C 的記憶體、日誌與工具鏈限制，後續依實際開發情境整理，平台差異由專案文件說明。

專案版 `coding-rules.md` 使用本專案可核對的模組、函式與設定舉例，並區分現行做法與待採用提案。這份專案文件中明訂的約定優先於本套共用與語言規則；衝突時依專案約定執行並指出差異，未另訂的部分繼續遵循共用與語言規則。例如：專案明訂僅使用全域 debug 開關時，不強制增加模組開關。
